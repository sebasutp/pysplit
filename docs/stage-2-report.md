# Stage 2 report — SQLModel schema, Alembic, legacy importer

Date: 2026-10-24
Stage: 2

## Outcome

The new backend owns the complete legacy schema (19 tables), split across three
Alembic revisions. A read-only, idempotent importer copies both confirmed
production fixture databases and a purpose-built edge-case fixture. The
verifier proves row equality, per-group aggregates, SQLite integrity, foreign
keys, and balances against fixtures generated by the reference `getBalances`
implementation.

- `types.py` — `UTCDateTime` (timezone-aware UTC round-trip) and
  `DecimalString` (exact decimal text, never float).
- `base.py` — `SyncColumns` (`updated_at`, `version`, `deleted_at`) and
  `utc_now`.

## Gate checklist

- [x] One model file per table; all 19 tables present.
- [x] Legacy Prisma field semantics preserved (nullable information/notes,
      `category_id` default 0, orphan documents/activities, composite join
      keys, receipt uniqueness).
- [x] Internal expense dates are UTC datetimes with microseconds and aware
      timezone; `Decimal` conversion rates are stored and read as exact text.
- [x] Money is integer minor units; booleans round-trip as `0`/`1`.
- [x] Required foreign keys, uniqueness constraints, composite primary keys
      and performance indexes exist.
- [x] `version` and `deleted_at` synchronization columns exist on synchronizable
      rows.
- [x] Alembic is split into `0001_core_schema`, `0002_receipts_schema`,
      `0003_sync_and_auth_schema`; down/up is clean.
- [x] Migration DDL and `SQLModel.metadata` produce the same schema (tested).
- [x] Import opens the source read-only and never modifies it.
- [x] Non-empty target is refused unless `--reset`; matching-checksum re-import
      is a no-op.
- [x] Dates, booleans and decimals are parsed exactly; timestamps are not
      truncated.
- [x] Missing default categories are seeded (40 for the edge fixture, 44 for
      the large fixture).
- [x] IDs and timestamps are preserved; sessions and verification tokens are
      not imported.
- [x] Orphan documents and activities are preserved.
- [x] Every run writes an `ImportRun` with checksum, counts and duration.
- [x] Verifier compares row equality, counts, per-group participants/expenses/

- [x] Balances match reference-generated golden fixtures for every confirmed
      database.
- [x] Zero missing rows, zero foreign-key violations, `integrity_check` = `ok`
      for all three fixtures.
- [x] Edge-case fixture covers every table.

## Deviations and open questions

1. **Golden generator path.** The plan names
   `spliit/scripts/export-legacy-balances.ts`, but `spliit/` is mounted
   read-only in this environment (`touch` fails with `Read-only file system`).
   The temporary generator therefore lives at
   `backend/scripts/reference/export-legacy-balances.ts` and imports the real
   `@/lib/balances` function from the reference tree. The generated fixtures
   record `generated_by: spliit/src/lib/balances.ts::getBalances`. No reference
   source file was modified.
2. **Virtualenv state.** `backend/.venv/lib` is a stale root-owned mount in this
   sandbox and cannot be removed. A working venv was created at
   `backend/.venv-work`, and `.venv/bin/*` symlinks point at it. Activating
   `.venv/bin/activate` works normally; `alembic`, `pytest`, `python`, `ruff`
   all resolve. The work venv is gitignored.
3. **Importer schema creation.** The importer creates the target schema from
   `SQLModel.metadata` so the documented single command works on a brand-new
   `/tmp/new.db`. Alembic remains the production path, and a test proves the
   migration DDL and metadata schema are identical. `alembic check` reports no
   drift.
4. **Sync columns on categories and users.** `Category` and `User` gain
   `updated_at`/`version`/`deleted_at` because the plan requires synchronization
   columns; the reference tables have no such columns. They are ignored by the
   verifier, which compares only legacy fields.
5. **No `Session` / `VerificationToken` tables.** They are deliberately absent
   rather than created-and-empty, preventing accidental migration later; the
   new `RefreshToken` table replaces them.
6. **Golden matching is checksum-based.** Copying a fixture to `/tmp` preserves
   its checksum, so verification finds the matching golden. An arbitrary
   production copy without a golden falls back to comparing target balances to
   source balances and reports that explicitly; `--require-golden` makes the
   stricter behaviour mandatory.
