# ADR 0003 — Authentication, authorization and guest access

Status: Accepted
Date: 2026-10-24
Related: ADR 0000 decision 3

## Context

The fork extends upstream Spliit with accounts (Google/GitHub OAuth), three
tiers (`sync_users`, `group_creators`, `admin`), cross-device group
synchronization and an admin dashboard. Upstream Spliit deliberately has no
accounts: a group URL is a capability. Both models must coexist.

The reference stores a custom HMAC-SHA256 JWT in a `spliit_session` cookie and
reloads the user tier from the database on every request. That is a useful
correctness property worth keeping, but a long-lived cookie is not.

## Decision

### Tokens

| Token | Form | Lifetime | Storage |
|---|---|---|---|
| Access | JWT (`sub`, `tier` optional, `exp`, `iat`, `jti`) | 15 minutes | SPA memory only |
| Refresh | opaque 256-bit random value, SHA-256 hashed at rest | 30 days, rotating | `HttpOnly; Secure; SameSite=Lax; Path=/api/auth` cookie |

- `POST /api/auth/refresh` validates the refresh cookie, detects reuse of an
  already-rotated token, revokes the whole token family on reuse, and returns a
  new access token plus a new refresh cookie.
- Logout revokes the presented refresh token and clears the cookie.
- `GET /api/auth/me` returns the current user from the database. Tier is
  **always** read from the database, so promotion/demotion is immediate even
  when the access token is still valid.
- The client attempts refresh on start. Offline, refresh is deferred and local
  access continues; an expired access token never blocks local reads/writes.

### OAuth

- `GET /api/auth/oauth/{google|github}/start` creates a random `state`, stores
  it in an `HttpOnly`, short-lived cookie, and redirects to the provider.
- The callback validates `state` in constant time and rejects a mismatch.
- `return_to` must be a normalized relative path on the same origin; absolute
  URLs and protocol-relative URLs are rejected.
- Provider profiles link to an existing user by verified email, otherwise a
  user is created with tier `sync_users`.
- Only Google and GitHub are enabled in v1.

### Tiers

| Tier | Capabilities |
|---|---|
| `sync_users` (default) | Read/write any group link; synchronize own group list; no group creation |
| `group_creators` | `sync_users` + create groups |
| `admin` | `group_creators` + all `/api/admin/*` endpoints and AI configuration visibility |

Tier is checked in a dependency after loading the user. `admin` endpoints use
`adminProcedure` equivalent (dependency `require_admin`). A missing/invalid
token returns 401; an authenticated user without the tier returns 403.

### Guest model

- Group endpoints remain **unauthenticated**. Anyone with the group URL can
  read and write, exactly like upstream Spliit. This is a capability URL, not
  privacy; documentation and admin UI must say so.
- Account-only features (group list synchronization, star/archive across
  devices, global balance, admin, AI quota accounting) require auth.
- Local guest groups are claimed on login by inserting `UserGroup` rows and
  merging IDs; no data is duplicated. The merge is queueable offline.

### CSRF and browser defenses

- Refresh and logout are cookie-authenticated mutations. They require a
  same-origin `Origin`/`Referer` check and a double-submit CSRF token.
- Access-token mutations use the `Authorization: Bearer` header, which is not
  sent automatically by browsers.
- Cookies are `HttpOnly`, `Secure` in production, `SameSite=Lax`, and scoped to
  `/api/auth`.
- Auth endpoints are rate limited per IP and per account.
- CORS is an explicit allowlist; credentials are allowed only for that list.

### Bootstrap

- There is no default admin. `python -m app.scripts.make_admin --email …`
  promotes or pre-authorizes a user.
- Production startup fails if `JWT_SECRET` is missing or equal to the
  development default.

## Consequences

- The SPA must refresh once on boot and retry one failed request after a 401.
- Offline sessions are usable until the access token is needed; server writes
  wait for refresh and surface `unauthorized` if refresh fails.
- Guest links keep working with no cookies, which preserves every existing
  shared URL.
- Admin and AI operations cannot be made offline without weakening this model.

## Rejected alternatives

- **Long-lived JWT cookie (reference behavior).** Rejected: no rotation, no
  revocation, and token theft has a year-long blast radius.
- **Bearer token in IndexedDB.** Rejected: readable by any script on the
  origin; memory + refresh cookie is safer.
- **Per-group ACLs.** Explicitly out of scope for v1; preserve capability URLs.
